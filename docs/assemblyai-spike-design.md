# One-mic EN/TR ASR proof

The authorized first deliverable is a bounded AssemblyAI proof using the existing browser PCM worklet and private WebSocket. Keep the original English/Spanish study session path. A new `assemblyai-proof` mode transcribes only; it does not start introductions, translate participants, speak Scripture, or claim human recognition has been verified. Human evidence gates a later conversational mixed-language slice.

`dbs_assemblyai.py` owns authenticated server-only provider transport, one connection per group, explicit Universal-3.6 Pro parameters, validation, idle/deadline limits, and termination. `dbs_mixed_turns.py` owns session-memory turn updates, final deduplication, cautious name-binding evidence, speaker revisions, and a translation eligibility policy. Speaker label, language code, confidence and verified name are distinct fields. Revisions revoke affected names and stale confidence. Unknown, PENDING, short and overlapping turns remain unattributed. A language preference never identifies a human.

`dbs_web.py` selects proof or existing study mode behind the same origin/host/consent checks. Proof audio is 16 kHz, mono, signed little-endian int16. Partial turns update a single display item; final/revised turns replace that item by turn order. No audio, voice embeddings or private transcripts are saved. The proof ends within three minutes, and on stop, stalled audio, invalid audio, disconnect, cancellation or provider failure. Shutdown waits briefly for revisions and Termination, then closes the socket.

`dbs_youversion.py` imports the existing YouVersion project's server integration without copying its credential file. Only official server-side GETs are allowed. Exact numeric version IDs, language, edition, Genesis verse coverage, copyright and publisher attribution are validated. Canonical Waha question availability is checked separately. ASR proof has no Scripture-reading feature; missing content readiness never triggers generated or translated Scripture.

Offline tests first exercise final-turn deduplication, revisions/PENDING/name evidence, language changes, mixed-only and playback translation gates, provider authentication/PCM parameters, stop/failure/cancellation cleanup, browser consent/security, and exact Scripture validation. Then run the existing regression suite. Use a bounded silence stream for real authentication/model/cleanup evidence; silence or synthetic speech cannot establish microphone transcription or multi-person diarization. A consenting human EN/TR one-mic trial is still required before the full mixed facilitator. External LLM API calls are prohibited.
